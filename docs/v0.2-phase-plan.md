# Moryn v0.2 Phase 1-6 Plan

This plan turns the v0.2 roadmap into executable work. The default product path
stays:

```text
setup -> context pack -> capture -> review -> approve -> sync
```

The two release invariants are:

- No silent canonical writes.
- Full evidence remains available in `/api/dashboard`.

## Global Acceptance Rules

- No ordinary capture or dashboard render writes canonical memory.
- Canonical memory changes only happen through explicit Capture Inbox, Review
  Queue, or Candidate Triage approval controls.
- Every approval writes append-only events and returns timeline/recall evidence.
- Private, secret, sensitive, raw, archived, and quarantined records remain
  hidden from default recall unless explicitly requested.
- `/api/dashboard` keeps machine-readable evidence even when visible HTML is
  collapsed or simplified.
- Main branch stays clean, dashboard runs on port `8765`, and Moryn store sync
  is clean after durable handoffs.

## Phase 1: Auditable Autocapture

**Objective:** Make capture reliable and automatic enough for normal handoffs,
while keeping every captured item reviewable and non-canonical by default.

**Already present:**

- `moryn context pack` provides Handoff Pack v0.2, quality gate, evidence, and
  required capture action.
- `moryn capture session` writes session-summary capture records.
- `default_autocapture_policy` routes low-risk handoffs to local evidence and
  risky/durable handoffs to Capture Inbox.
- `capture_policy` explains capture decisions read-only.

**Execution list:**

- Add host-adapter regression tests for `codex`, `claude`, `gemini`, `cursor`,
  and `shell`.
- Prove captured records include source client, project id/path, task summary,
  session id when available, touched files when supplied, risk tags, and
  `host:<client>` tags.
- Prove low-risk auto-capture remains `raw` or `candidate`, never `canonical`.
- Prove durable/risky handoffs enter Capture Inbox with source, task, summary,
  project, risk reason, and timeline command.
- Prove duplicate smoke/demo captures are policy-archived and do not create
  dashboard review noise.
- Add CLI/MCP parity checks for `capture session` and `capture_policy`,
  including supported camelCase MCP aliases.
- Add dashboard/API evidence assertions that Capture Inbox rows trace back to
  `capture_policy` decisions without exposing private content by default.
- Update `docs/agent-workflow.md` with when capture happens automatically and
  one routed-to-review example.
- Update `docs/contracts.md` if capture-policy evidence paths or action ids
  change.

**Tests and acceptance:**

- `npx vitest run tests/core/engine.test.ts tests/cli/cli.test.ts tests/mcp/server.test.ts --reporter=dot`
- `npx vitest run tests/observability/dashboard.test.ts tests/docs-contract.test.ts --reporter=dot`
- `npm run smoke:dogfood-demo`
- `npm run typecheck`
- `git diff --check`

Phase 1 is accepted when a fresh dogfood demo proves both low-risk autocapture
and review-routed capture, no path auto-promotes canonical memory, and every
captured item can be audited back to source and policy reason.

## Phase 2: Memory Governance

**Objective:** Make saved-but-not-yet-long-term content understandable and
safely actionable without turning the dashboard into a busy admin console.

**Already present:**

- Capture Inbox, Review Queue, Candidate Triage, Memory Doctor, Memory
  Lifecycle, Dogfood Notes, and dashboard decision summary exist.
- Approval controls are explicit and append-only.
- Dashboard copy distinguishes saved/searchable content from real decisions.

**Execution list:**

- Define one shared approval brief shape across Capture Inbox, Review Queue,
  and Candidate Triage: change, scope, write boundary, stale guard, evidence
  commands, and trace note.
- Add tests proving all approval surfaces use the same approval brief language.
- Add stale-guard tests for stale candidate, stale group, stale review plan, and
  stale promotion draft.
- Add archive/reject tests proving rejected items stay traceable and do not
  disappear destructively.
- Add duplicate/stale/conflict fixtures to Memory Doctor/Lifecycle tests.
- Verify recommended actions point to promote, archive, quarantine, revise,
  link, or timeline commands.
- Add dashboard assertions that `Needs your decision` only appears for real
  pending writes, not ordinary saved content.
- Add dashboard assertions that saved content search, filters, and detail panes
  stay read-only and keep selected item state stable across refresh.
- Expand `docs/dashboard.md` for `saved for later`, `saved briefly`, and
  `set aside` in user-facing language.

**Tests and acceptance:**

- `npx vitest run tests/core/engine.test.ts --reporter=dot`
- `npx vitest run tests/observability/dashboard.test.ts --reporter=dot`
- `npx vitest run tests/docs-contract.test.ts --reporter=dot`
- Manual dashboard smoke at `http://43.167.207.41/moryn-dashboard/`
- `npm run typecheck`
- `git diff --check`

Phase 2 is accepted when a user can answer "what is saved?" and "do I need to
act?" without reading raw logs, every canonical write requires explicit
approval, and rejected/archived/quarantined content remains auditable.

## Phase 3: Setup Wizard

**Objective:** Keep setup boring, local, and trusted: dry-run by default, safe
local apply, clear next actions when blocked.

**Already present:**

- `moryn setup` dry-run plan exists.
- `moryn setup --apply` initializes Moryn-local store/project config and avoids
  host config mutation.
- CLI, MCP, operation contracts, and selection-source contracts expose setup.
- `health_check` provides read-only installation trust checks.

**Execution list:**

- Add test coverage proving dry-run lists every planned local write with path,
  action, reason, and whether it requires `--apply`.
- Add test coverage proving `--apply` never edits host config files unless a
  future task adds rollback receipt and smoke coverage.
- Add failure-output tests for missing Git, invalid project path, invalid sync
  remote, unreadable store, and dirty/conflicting sync state.
- Ensure every setup/health failure includes executable next actions rather
  than prose-only troubleshooting.
- Add package-installed smoke coverage for `moryn setup`, `moryn health check`,
  and `moryn context pack` without dev dependencies.
- Tighten README setup so the first successful path is short and advanced host
  details move to docs.

**Tests and acceptance:**

- `npx vitest run tests/cli/cli.test.ts tests/mcp/server.test.ts tests/package-smoke.test.ts --reporter=dot`
- `npx vitest run tests/docs-contract.test.ts --reporter=dot`
- `npm run smoke:dogfood-demo`
- `npm run typecheck`
- `git diff --check`

Phase 3 is accepted when a new user can run dry-run setup, understand exactly
what would change, apply only Moryn-local setup, and recover from blocked setup
with executable next actions.

## Phase 4: Recall Eval

**Objective:** Make recall quality measurable with read-only evals before any
semantic or embedding plugin is considered.

**Already present:**

- Minimal `recall_eval` / `moryn eval recall` path exists.
- Eval reports include golden queries, expected record ids, privacy checks,
  ranking reasons, provenance, and read-only follow-up commands.

**Execution list:**

- Add a compact golden-query fixture set covering memory, skill,
  preference/soul, session summary, agent note, archived, quarantined, raw,
  sensitive, and project-scoped records.
- Add tests for expected ids, missing expected ids, excluded private/sensitive
  ids, stale/conflict detection, and provenance coverage.
- Add eval output that recommends hygiene actions only as suggestions: revise,
  archive, promote, add tags, or follow timeline.
- Add dashboard/API evidence for latest recall-eval summary without making it a
  first-screen decision.
- Add docs showing how to create a tiny eval case and interpret failures.
- Add a guardrail test proving eval is read-only by comparing event count
  before and after.

**Tests and acceptance:**

- `npx vitest run tests/core/engine.test.ts tests/cli/cli.test.ts tests/mcp/server.test.ts --reporter=dot`
- `npx vitest run tests/observability/dashboard.test.ts tests/docs-contract.test.ts --reporter=dot`
- `npm run typecheck`
- `git diff --check`

Phase 4 is accepted when eval can identify missing, hidden, stale, or poorly
ranked memory without changing the store, and docs explain eval without
positioning Moryn as a vector-memory SDK.

## Phase 6: Release Gate

**Objective:** Close v0.2.0 with reproducible verification, clean package
contents, live dashboard health, and synced Moryn store evidence.

**Already present:**

- `release:check`, `smoke:dogfood-demo`, and `smoke:agent-lifecycle` scripts
  exist.
- Package contents are checked by release tests.
- Dashboard can be restarted and health-checked at the canonical URL.
- Moryn store can be updated through `agent finish` and pushed to
  `moryn-store`.

**Execution list:**

- Run `npm run typecheck`.
- Run `npm test`.
- Run `npm run release:check`.
- Run `npm run smoke:dogfood-demo`.
- Run `npm run smoke:agent-lifecycle`.
- Run `npm pack --dry-run --json` and inspect output for private store data,
  generated dashboard snapshots, tarballs, or local-only docs.
- Run `git diff --check`.
- Restart dashboard using only the canonical 8765 command.
- Confirm `http://43.167.207.41/moryn-dashboard/healthz` returns `200`.
- Fetch `http://43.167.207.41/moryn-dashboard/` and confirm first-screen
  anchors exist: `Do I need to act?`, `What Moryn remembers`,
  `Recently saved`, and shared-copy state.
- Run `node --import tsx src/cli.ts sync --status` and confirm clean sync.
- Write final `moryn agent finish` summary to `moryn-store` with commit, tests,
  dashboard PID, healthz status, and release caveats.
- Confirm `moryn-store` sync is clean after the handoff.
- Commit and push final release-prep docs/code on `main`.

**Tests and acceptance:**

- `npm run typecheck`
- `npm test`
- `npm run release:check`
- `npm run smoke:dogfood-demo`
- `npm run smoke:agent-lifecycle`
- `npm pack --dry-run --json`

- `curl -fsS -o /tmp/moryn-dashboard-health.txt -w '%{http_code}' http://43.167.207.41/moryn-dashboard/healthz`

- `node --import tsx src/cli.ts sync --status`

Phase 6 is accepted when every command above exits 0, package contents are
manually inspected as safe, dashboard is live with latest main-branch code, Git
worktree is clean, Moryn store sync is clean, and final handoff records exact
commit, verification commands, dashboard PID, and known remaining risks.

## Cross-Phase Execution Order

1. Finish Phase 1 and Phase 2 together where tests overlap: capture routing and
   governance approval are one user flow.
2. Finish Phase 3 next because setup trust is the front door for public use.
3. Finish Phase 4 after governance is stable so eval recommendations point to
   mature actions.
4. Finish Phase 5 after behavior is stable, so public copy does not chase
   moving internals.
5. Run Phase 6 last as the release gate.

## Final v0.2.0 Definition of Done

- The default dogfood path works end to end: setup, context pack, capture,
  review, approve, sync.
- Saved content is searchable and understandable without becoming a forced
  decision.
- Long-term memory writes are explicit, append-only, and auditable.
- Setup is dry-run safe and package-installed smoke tested.
- Recall quality can be measured read-only.
- Public docs explain Moryn as a user-owned, auditable context store and
  handoff layer.
- Release gate commands pass, dashboard is live, repo is clean, and Moryn store
  sync is clean.
