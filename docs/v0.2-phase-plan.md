# Moryn v0.2 Phase 1-6 Plan

This plan turns the v0.2 roadmap into executable work. It is a temporary
development tracker. After v0.2 is complete, keep the public-facing product
truth in `README.md`, `docs/moryn-design.md`, `docs/agent-workflow.md`,
`docs/dashboard.md`, and `docs/contracts.md`, then delete this file.

The default product path stays:

```text
setup -> context pack -> capture -> review -> approve -> sync
```

```text
+---------+      +--------------+      +---------+      +---------+      +----------+      +------+
| setup   | ---> | context pack | ---> | capture | ---> | review  | ---> | approve  | ---> | sync |
| dry-run |      | read-only    |      | saved   |      | human   |      | explicit |      | Git  |
+---------+      +--------------+      +---------+      +---------+      +----------+      +------+
     |                  |                    |                |                 |              |
     v                  v                    v                v                 v              v
local writes      Handoff Pack v0.2     raw/candidate    dashboard/CLI     append-only    user-owned
only when         quality gate          by default       decision          canonical     shared copy
applied           evidence paths        no promotion     boundary          event
```

The two release invariants are:

- No silent canonical writes.
- Full evidence remains available in `/api/dashboard`.

## Phase Gate Checklist

Every work package should follow the same loop:

```text
write failing focused test
  -> implement the smallest behavior/docs change
  -> run focused verification
  -> run the phase gate commands
  -> commit on main
  -> push
  -> record durable progress in moryn-store
  -> restart dashboard when dashboard UI/API or served docs changed
```

Each phase is accepted only when all of these are true:

- Required tests for the phase pass.
- `npm run typecheck` passes.
- `git diff --check` passes.
- New or changed user-facing behavior is documented.
- Main is clean after commit.
- Durable progress is written through `moryn agent finish` when the slice changes
  product behavior, public docs, or release status.

## Global Acceptance Rules

- No ordinary capture or dashboard render writes canonical memory.
- Canonical memory changes only happen through explicit Capture Inbox, Review
  Queue, Candidate Triage, or CLI/MCP mutation commands with explicit user
  authority.
- Every approval writes append-only events and returns timeline/recall evidence.
- Private, secret, sensitive, raw, archived, and quarantined records remain
  hidden from default recall unless explicitly requested.
- `/api/dashboard` keeps machine-readable evidence even when visible HTML is
  collapsed or simplified.
- Saved content is searchable and understandable without becoming a forced user
  decision.
- Dashboard first screen answers three plain questions: do I need to act, what
  did Moryn save, and is the shared copy current.
- Main branch stays clean, dashboard runs on port `8765`, and Moryn store sync
  is clean after durable handoffs.
