# Migrating to Moryn v0.5

Moryn v0.5 opens v0.2, v0.3, and v0.4 stores in place. It does not rewrite
append-only event history and does not require a migration command.

## Install and verify

```bash
npm install -g @richardyu114/moryn@0.5.0
moryn --version  # 0.5.0
moryn health check --project . --host <host>
moryn rebuild
```

Use v0.5 consistently on devices that publish to the same remote. Older
clients do not enforce the v0.5 local-event and origin boundaries.

## Local-only records and sync

New `local_only` records are written to an ignored local event journal and are
merged into local reads without entering normal Git publication. Inspect policy
before the first v0.5 push:

```bash
moryn sync preflight --destination personal_sync --mode shadow
moryn sync preflight --destination personal_sync --mode enforce
moryn sync --push
```

This is a prospective boundary. If an older release already committed a payload
to Git, upgrading does not erase that history.

## Host lifecycle activation

Re-run a dry-run before applying host integration changes:

```bash
moryn install --host <codex|claude> --project .
moryn install --host <codex|claude> --project . --apply --activate-host
moryn continuity negotiate --host <codex|claude|opencode>
```

Codex and Claude Code recovery after compaction uses
`SessionStart(source=compact)`. Generated integrations do not install or claim a
PostCompact handler. OpenCode uses MCP or CLI unless a separate lifecycle plugin
is installed.

## Repo Atlas

Run one scan in each checkout:

```bash
moryn repo-atlas scan --repo .
moryn repo-atlas view --repo . --lens onboarding
```

A schema-v1 snapshot is readable but causes a complete v2 rescan. Claims remain
append-only. Stale evidence must be reviewed and explicitly reverified; Moryn
does not rewrite a claim statement when code changes.

## Remote paths and workspace mappings

Recall and timeline output can mark a path as remote or unknown. Do not access
that path directly. Register a device-local mapping, then resolve the exact
source path:

```bash
moryn workspace map set \
  --project-id <project_id> \
  --source-device-id <source_device_id> \
  --source-root <remote_checkout_root> \
  --local-root <verified_local_checkout_root>

moryn workspace map resolve \
  --project-id <project_id> \
  --source-device-id <source_device_id> \
  --source-path <remote_path>
```

Mappings stay under local `state/` storage and are not synchronized. A result is
safe to access only when the target exists and its real path remains inside the
mapped local root.

## Downgrade boundary

v0.4 can read ordinary synchronized events but cannot interpret or enforce all
v0.5 context infrastructure. Before a temporary downgrade, stop writes and
sync, retain the v0.5 local state directory, and do not publish local-only
content through an older client. Returning to v0.5 requires no event rewrite;
run `moryn rebuild` and repeat the health check.
